## 3 คำถามที่ต้องตอบ

## 1. ทำไมโปรเจกต์นี้เลือก SQLite แทน MongoDB

โปรเจกต์ Campus Service มีข้อมูลที่มีโครงสร้างชัดเจน เช่น ผู้ใช้งาน (users) และคำร้อง (requests) และมีความสัมพันธ์ระหว่างข้อมูล โดยคำร้องแต่ละรายการจะอ้างอิงผู้แจ้ง จึงเหมาะกับฐานข้อมูลแบบตารางอย่าง SQLite มากกว่า นอกจากนี้ SQLite เก็บข้อมูลเป็นไฟล์ภายในโปรเจกต์ ทำให้ตั้งค่าและใช้งานได้ง่าย เหมาะกับขนาดของระบบและการพัฒนาในโปรเจกต์นี้

## 2. ถ้าวันหนึ่งต้องเปลี่ยนไป MongoDB จะกระทบชั้นไหนบ้าง

ถ้าเปลี่ยนจาก SQLite เป็น MongoDB จะกระทบ Service และ Controller เพราะ Service เดิมของเราติดต่อ SQLite แบบ synchronous แต่ MongoDB ใช้การติดต่อฐานข้อมูลแบบ asynchronous ทำให้ Service ต้องเปลี่ยนมาใช้ async/await และคืนค่าเป็น Promise เมื่อ Controller เรียก Service ก็ต้องปรับให้รองรับการทำงานแบบ asynchronous และจัดการ await หรือข้อผิดพลาดด้วย ดังนั้นครั้งนี้จึงไม่ได้แก้เฉพาะ Service เหมือนการแก้ไขในครั้งก่อน ๆ

## 3. async จำเป็นเมื่อไร ไม่จำเป็นเมื่อไร

- จำเป็น เมื่อฐานข้อมูลอยู่คนละเครื่องกับ API เพราะการติดต่อข้อมูลต้องส่งผ่านเครือข่ายและใช้เวลาในการรอผลลัพธ์ จึงควรใช้ async/await เพื่อให้โปรแกรมสามารถจัดการการทำงานระหว่างรอข้อมูลได้
- ไม่จำเป็น เมื่อฐานข้อมูลอยู่ในเครื่องเดียวกันกับ API เช่น SQLite ที่เก็บเป็นไฟล์ในเครื่อง เพราะสามารถอ่านและเขียนข้อมูลตามลำดับการทำงานได้ โดยไม่ต้องรอการติดต่อกับเครื่องอื่น
